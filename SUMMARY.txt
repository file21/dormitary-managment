OOP PRINCIPLES DEMONSTRATED IN CODE
================================================================================

1. ENCAPSULATION
   Files: model/User.java, model/Bed.java, model/DormApplication.java
   Key: All fields private, accessed only via getters
   Result: Safe, immutable objects

2. ABSTRACTION
   Files: service/ScoringPolicy.java, service/DefaultScoringPolicy.java
   Key: Interface hides implementation complexity
   Result: Simple interface, flexible implementations

3. INHERITANCE
   Files: model/User.java (parent), Student/Admin/Proctor.java (children)
   Key: Shared behavior in parent, specific in children
   Result: No code duplication

4. POLYMORPHISM
   Files: Any code using User, Student, Admin, Proctor interchangeably
   Key: Same variable can hold different types at runtime
   Result: Flexible, extensible code

5. SOLID PRINCIPLES
   ✓ Single Responsibility: Each service has one job
   ✓ Open/Closed: Extend via interfaces, don't modify
   ✓ Liskov Substitution: Subtypes replace parent types
   ✓ Interface Segregation: Focused interfaces, not bloated
   ✓ Dependency Inversion: Depend on interfaces, not implementations

KEY POINTS TO EMPHASIZE
================================================================================

1. "Why private fields?"
   → Encapsulation - prevents invalid states, makes code safer

2. "Why inheritance hierarchy?"
   → DRY principle - don't repeat code, inherit common behavior

3. "Why interfaces?"
   → Dependency Inversion - can swap implementations without changing service

4. "Why separate services?"
   → Single Responsibility - each class has one reason to change

5. "How would you add features?"
   → Open/Closed - extend through new classes, don't modify existing ones
